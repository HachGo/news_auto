# AI 工业革命动态观测台（Prediction Engine V2）设计

日期：2026-11-22 · 状态：一期（四指数、金融压力、资本投入）与二期（八张图 + 时间轴回放）已实现

## 1. 目标与约束

- 新页面 `/revolution/`（中英双语），D/B/S/C 指数看板、八类动态图、时间轴回放、多指标对比、历史事件标记、预测回测、数据来源详情。
- 沿用 Hugo + GitHub Pages；图表用 Apache ECharts 5.6.0（自托管在 `assets/js/vendor/`，只在本页加载）。
- 数据由 Python 在每日 GitHub Actions 中计算，导出为版本化 JSON。
- 每条序列标注证据类别：真实观测 / 代理估算 / 历史研究示意 / 模型预测。无数据不填补；发布频率与发布滞后逐项展示。
- 首页只加一张入口卡片，主导航不变（测试保证）。

## 2. 指数定义

| 指数 | 含义 | 入指数成分 | 只展示 |
|---|---|---|---|
| D 采用扩散 | AI 在企业与劳动力中的扩散 | 计算机系统设计业就业同比（代理） | Indeed 软件开发岗位指数（方向不确定） |
| B 资本与基建 | 资本投入增速 | 四大云厂商资本开支同比（EDGAR）、信息处理设备投资同比、软件投资同比（BEA） | 占 GDP 比重 |
| S 金融压力 | 金融状况与估值热度，越高越紧 | NFCI、STLFSI4、费城半导体指数相对三年均线偏离（代理） | VIX、高收益债利差（FRED 只有 3 年） |
| C 能力与算力 | 前沿算力与芯片产出 | 前沿训练算力 12 个月增量（Epoch，研究估算）、半导体产出同比（代理） | Epoch 模型散点 |

指数 = 50 + 10 × 平均(方向 × 扩展窗口 z，截断 ±4σ)。每个月只用「观测期末 + 发布滞后 ≤ 月末」的数据，过旧视为缺失；缺失成分不填补，只降低覆盖率。回放使用最新修订值（非实时版本），页面注明。

待接入（页面如实列出）：Census BTOS 企业 AI 使用率、数据中心建设支出、EIA 数据中心用电。

## 3. 预测设计（重新考虑后的方案）

**不直接预测合成指数。** D/B/S/C 是本站自定权重的合成量，成分频率不一（周 / 月 / 季 / 不定期）、部分历史很短（云厂商资本开支同比可连续使用的只有 2018 年以后约 33 个季度）。直接预测合成指数既循环（改权重就改写历史与目标）又没有可结算的真实目标。

改为**成分级预测 + 上线门槛**：

| 环节 | 做法 |
|---|---|
| 预测对象 | 可观测成分，按自身频率预测后 h 期：周度 4 / 13，月度 1 / 3，季度 1 / 2 |
| 基准 | 不变预测（随机游走）。增速与金融状况高度持续，这个基准很难打败 |
| 模型 | 直接多步回归 y(t+h) = a + b·y(t)，扩展窗口；样本从 1990 年起，避开 1960–80 年代软件投资等序列的早期结构 |
| 区间 | 所用方法过去样本外误差的经验 10% / 90% 分位；样本外误差 < 20 个不给区间 |
| 门槛 | 样本外 ≥ 40 点、MSE 技能分 ≥ 1%、DM 单侧 p < 0.05 才显示模型；不足 40 点标「样本不足 · 仅示意」 |
| 阈值概率 | NFCI / STLFSI4 13 周后 > 0。基准 = 不变预测 + 其误差分布；**不用无条件发生率作基准**——初版这样做时技能分虚高到 +64%，那只是「知道当前水平」的作用 |
| 指数衍生预测 | 成分点预测换算为 z 后按指数规则平均；没有预测的成分保持当前 z（否则构成变化会让读数凭空跳动，初版 S 指数因此显示 −2.8 的假下行）。标「衍生」，不计分 |
| 实盘记录 | `history/revolution/forecast_log.jsonl` 每个新起点登记一次；`resolution_log.jsonl` 目标期首次出现真实值时结算一次。两者只追加，后续修订不改写 |

## 4. 数据与产物

来源均无需 API Key：FRED 公开 CSV、SEC EDGAR XBRL companyconcept（UA 不含个人邮箱，可用 `SEC_USER_AGENT` 覆盖）、Epoch AI CSV、Yahoo（^SOX），VIX 复用资产走势模块缓存。

- EDGAR 现金流量表是年初至今累计：单季 = 本期累计 − 同起点上一季累计；同一期间多次申报取最晚（含修订）；亚马逊 2017 年换标签、Alphabet 2015 年前在 Google 旧 CIK 下，均已合并。Amazon 2017Q2 在 XBRL 中未披露，保留为缺失并在来源表列出。
- 原始缓存：`history/revolution/*.csv`（不放 `data/`，Hugo 会解析）。抓取失败沿用缓存并在来源表标注。
- 版本化 JSON：`static/data/revolution/v1/{manifest,indices,series,forecasts,events}.json`，manifest 带每个文件的 sha256 前缀，前端以此做缓存失效；结构不兼容时升 v2。
- Hugo 摘要：`data/radar/revolution.json`（卡片、预测表、来源表），无 JS 时页面数字完整。

## 5. 图表规范

- 四个指数用分类色槽 1–4（蓝 / 橙 / 青 / 黄），dataviz 校验脚本对浅色 #ffffff、深色 #18181b 表面均通过（相邻 CVD ΔE ≥ 8.4）；浅色下青、黄对比度 < 3:1，故保留端点直接标注与表格视图。深色为单独选定的色阶。
- 不用双纵轴：金融压力、采用扩散、半导体周期都按单位分面、共用时间轴与缩放。
- 颜色跟随实体：多指标对比中取消选择不会让其余指标换色。
- 全页一行筛选（1 / 3 / 5 / 10 年 / 全部 + 事件开关）作用于所有图；资本投入「占 GDP」视图固定全历史（需与互联网周期对照）。
- 数据文件中的标签（如 Epoch 模型名）进入 tooltip 前一律转义。

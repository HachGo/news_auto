# 股市与经济模块 · 整站按版面分离重构 设计规格

- **日期**：2026-08-01
- **状态**：已确认，待编写实现计划
- **背景**：现有 `news_auto` 是每天一篇大文章（含 AI 动态/社区热点/深度精选/国际新闻多板块）。用户要新增「股市与经济」模块，并借机把整站重构为按版面分离的结构。

## 1. 目标与定位

新增市场与宏观内容，同时把整站从「每日一篇大杂烩」重构为「按版面分离」：三大版面各自独立，每天各一篇，有独立列表页与归档。

**内容定位**（用户明确）：四类内容全要，但只要**概览/摘要**（中文 2-3 句话），重要时用户自行深入。不追求实时行情、不抓全文。

## 2. 信息架构

### 2.1 三大版面划分

| 版面 | 路径 | 含原分类 |
|---|---|---|
| ① AI 与科技社区 | `content/ai/` | AI 动态 + 社区热点 |
| ② 国际与深度 | `content/world/` | 国际新闻 + 深度精选 |
| ③ 市场与宏观（新增） | `content/market/` | 行情速览 + 宏观与政策 + 财经要闻 + 公告与研报 |

原「深度精选」并入国际与深度版面；社区热点并入 AI 与科技社区版面。

### 2.2 目录结构

```
content/
├── ai/               # ① AI 与科技社区
│   ├── _index.md     # 版面列表页
│   └── 2026-08-01.md # 每日文章
├── world/            # ② 国际与深度
│   ├── _index.md
│   └── 2026-08-01.md
├── market/           # ③ 市场与宏观（新增）
│   ├── _index.md
│   └── 2026-08-01.md
├── _index.md         # 首页：今日总览（脚本生成）
├── archives.md

```

### 2.3 导航菜单（`hugo.toml`）

```
首页 | AI | 国际 | 市场 | 归档 | 标签 | 搜索
```

### 2.4 首页形态：版面分离 + 今日总览（变体 B）

首页保留跨版面「今日焦点 3 条」（AI/国际/市场各取 1 条最高分），下方是三张版面摘要卡片（版面名 + 今日条数 + 1 句话概要 + 「查看全文 →」链接），点入看完整列表。PaperMod 的 `homeInfoParams` 保留站点标题/简介，正文区改为脚本生成的今日总览。

## 3. 数据源映射

### 3.1 市场与宏观的四类内容

| 子板块 | 内容 | 数据源 | 抓取方式 |
|---|---|---|---|
| 行情速览 | A股（上证/深证/创业板/成交额/北向资金）+ 港股（恒生/恒科）+ 美股（标普/纳指/道指）+ 商品（黄金/原油）+ VIX | 东方财富 push2 公开接口 | 非官方 API，JSON |
| 宏观与政策 | 当日数据发布日历（CPI/PMI/社融/LPR 等）+ 央行/证监会/统计局动态 | 金十数据经济日历页 | 页面抓取 |
| 财经要闻 | 财新 / 第一财经 / 华尔街见闻 / 三大证券报 / 界面·澎湃 | 各站 RSS | 复用现有 RSS 流程 |
| 公告与研报 | 巨潮公告摘要（年报/重大事项/停复牌）+ 券商宏观策略研报要点 | 巨潮公告列表页 + 慧博/发现报告 RSS | 公告抓页面，研报走 RSS |

### 3.2 AI / 国际两版面

数据源 URL 维持现有 `feeds.yaml` 不变。原 `category` 字段（AI 动态/社区热点/深度精选/国际新闻）需归并映射到新 section：

| 原 category | 归入 section |
|---|---|
| AI 动态、社区热点 | `ai` |
| 国际新闻、深度精选 | `world` |

`feeds.yaml` 增加按 section 分组的结构（或新增 `section` 字段），便于生成器按版面拉取自己负责的源。

### 3.3 降级策略

行情/宏观/公告每个抓取点独立 try/except，失败时该子板块当天渲染为「📊 数据获取失败，请稍后查看原文」占位，不影响其他子板块和其他版面。RSS 不可用时复用现有「原始英文摘要」降级。

## 4. 脚本架构

### 4.1 目录结构

```
scripts/
├── fetch_news.py          # 主入口，编排三大版面生成 + 首页总览
├── feeds.yaml             # RSS 源清单（扩展：加财经要闻/研报源，按 section 分组）
├── sources/               # 数据源抓取器（新增）
│   ├── __init__.py
│   ├── rss.py             # RSS 抓取（从 fetch_news.py 抽出，三版面共用）
│   ├── eastmoney.py       # 东方财富行情接口
│   ├── jin10.py           # 金十宏观日历页面
│   └── cninfo.py          # 巨潮公告列表页
├── generators/            # 版面生成器（新增）
│   ├── __init__.py
│   ├── ai.py              # ① AI 与科技社区
│   ├── world.py           # ② 国际与深度
│   └── market.py          # ③ 市场与宏观
├── common.py              # 共享：seen.json、LLM 客户端、渲染工具
└── requirements.txt       # 加 lxml / beautifulsoup4
```

### 4.2 主流程 `fetch_news.py`

```
1. 加载 feeds.yaml + seen.json
2. 顺序调度三个生成器：
   - ai.generate()      → content/ai/YYYY-MM-DD.md
   - world.generate()   → content/world/YYYY-MM-DD.md
   - market.generate()  → content/market/YYYY-MM-DD.md
3. 汇总三版面今日焦点 → 生成首页 content/_index.md（今日总览）
4. 更新 seen.json
```

三版面在同一个 GitHub Actions 任务里一起生成，一次提交（沿用现有 cron `0 23 * * *` = 北京 07:00）。

### 4.3 复用与隔离

- `common.py` 承载 `load_seen/save_seen`、`build_llm_client`、`link_hash`、`strip_html`、`render_item` —— 三版面共用
- 每个生成器只负责自己版面的「候选→筛选→摘要→渲染」
- 市场生成器内部调用 `sources/` 抓取器，抓取器有独立降级，生成器不感知抓取失败细节

**拆分动机**：现有 `fetch_news.py` 已 460 行，加市场后必超 800 行，单文件难维护。拆分后每个文件聚焦单一职责，符合现有代码「函数小、职责清」的风格。

## 5. 市场版面生成器内部流程

`generators/market.py`：

```
market.generate(date)
├─ 1. 行情速览  sources.eastmoney.fetch_quotes()
│     ├─ A股指数/成交/北向  → push2.eastmoney.com/api/qt/...
│     ├─ 港股/美股/商品/VIX → 同接口不同参数
│     └─ 失败 → 行情块渲染"数据获取失败"占位
├─ 2. 宏观日历  sources.jin10.fetch_calendar()
│     ├─ 抓金十经济日历页面，提取当日公布项
│     └─ 失败 → 宏观块渲染占位
├─ 3. 财经要闻  sources.rss.fetch(feeds.market_news)
│     ├─ 走现有 RSS 流程（已按时间窗口+去重过滤）
│     └─ LLM 翻译摘要（复用 common.summarize）
├─ 4. 公告与研报
│     ├─ sources.cninfo.fetch_announcements()  → 巨潮列表页
│     │   └─ 失败 → 公告块占位
│     └─ sources.rss.fetch(feeds.research)     → 研报 RSS
│         └─ LLM 摘要
└─ 5. 渲染 content/market/YYYY-MM-DD.md
      ├─ 行情速览（表格：指数/涨跌幅/成交额）
      ├─ 宏观与政策（日历列表 + 动态）
      ├─ 财经要闻（编号列表，同现有样式）
      └─ 公告与研报（编号列表）
```

### 5.1 LLM 加工范围

呼应「概览即可」定位：
- 行情数字、日历、公告标题 → **不经过 LLM**，直接结构化展示
- 财经要闻、研报 → **经 LLM 翻译摘要**（复用现有 `summarize`，2-3 句话）

### 5.2 行情速览渲染样式

```markdown
| 指数 | 点位 | 涨跌幅 |
|---|---|---|
| 上证指数 | 3225.43 | ▲0.82% |
| 深证成指 | 10243.1 | ▲1.12% |
| ... | | |
```

成交额、北向资金作为表格下方的摘要行。

### 5.3 宏观日历

当日有数据公布就列「指标 / 预期 / 前值 / 公布值」，没有则显示「今日无重要数据公布」。

### 5.4 错误隔离边界

四个子板块各自独立 try/except。最坏情况：行情、宏观、公告全失败，只剩财经要闻 —— 仍是一篇有效文章，不会因抓取失败导致整个市场版面缺失。

## 6. 首页今日总览生成

首页 `content/_index.md` 由脚本生成（不再手写），每天随三版面一起更新。

### 6.1 生成逻辑

```
1. 读取三个版面今日文章的 frontmatter + 焦点条目
2. 跨版面「今日焦点」3 条：
   - 从 AI 版面取 1 条最高分
   - 从 国际版面取 1 条最高分
   - 从 市场版面取 1 条：优先取财经要闻里最高分条目；若当日无财经要闻，则取行情速览首条指数（如上证指数涨跌幅最显著者）
3. 各版面摘要卡片：版面名 + 今日条数 + 1 句话概要 + 「查看全文 →」链接
4. 渲染 _index.md
```

### 6.2 首页内容形态

```markdown
---
title: "首页"
---

## 今日焦点

- **DeepSeek V4 Flash 0731 权重发布** 〔AI 与科技社区〕→
- **西班牙休达越境致 57 死** 〔国际与深度〕→
- **7 月 PMI 49.4，低于荣枯线** 〔市场与宏观〕→

## 各版面

### AI 与科技社区
今日 8 条 · 焦点：DeepSeek V4 发布、Anthropic 安全测试…
[查看全文 →](/ai/2026-08-01/)

### 国际与深度
今日 7 条 · 焦点：西班牙休达越境、刚果埃博拉…
[查看全文 →](/world/2026-08-01/)

### 市场与宏观
今日行情速览 + 12 条要闻 · 焦点：PMI 49.4、央行逆回购…
[查看全文 →](/market/2026-08-01/)
```

### 6.3 降级

某版面当天生成失败时，首页对应卡片显示「今日生成异常，查看历史 →」并链接到该版面列表页，不影响其他版面卡片展示。

## 7. 错误处理、测试与迁移

### 7.1 错误处理（三层防线）

1. **抓取层**（`sources/`）：每个抓取器 3 次重试 + 指数退避（复用现有 `fetch_feed` 的 429 处理模式），全部失败返回 `None`
2. **生成层**（`generators/`）：子板块级别 try/except，失败渲染占位块；整个版面生成失败时跳过该版面文章，不阻塞其他版面
3. **主流程**：三版面顺序生成，任一版面异常被捕获记录，继续下一个；首页总览根据实际成功生成的版面组装

### 7.2 LLM 失败处理（沿用现有策略）

- 重要性排序失败 → 降级为来源均衡（现有 `select_items`）
- 翻译失败 → 降级为原始摘要（现有行为）
- 市场版面 LLM 全失败但行情/日历/公告是结构化数据 → 仍可发布（结构化部分不依赖 LLM）

### 7.3 测试策略

- **抓取器单测**：用本地 fixture（保存的 HTML/JSON 样本）测试解析逻辑，不发真实请求 —— 避免依赖外部站点稳定性
- **生成器单测**：mock 抓取器返回值，验证渲染出的 Markdown 结构正确（焦点区、分类、占位块）
- **降级测试**：mock 抓取器返回 `None`，确认占位块正确渲染、不影响其他子板块
- **不写**：真实网络抓取的集成测试（CI 环境不稳定，且 GitHub Actions 每日跑就是事实集成测试）

### 7.4 依赖新增

```
lxml>=5.0
beautifulsoup4>=4.12
```

页面抓取用；RSS 仍用现有 feedparser。

### 7.5 迁移计划

1. 写 `scripts/migrate_posts.py`：扫描 `content/posts/*.md`，按原 frontmatter 分类标签把文章移到 `ai/` 或 `world/`
2. 删除旧 `content/posts/` 目录
3. 更新 `hugo.toml` 菜单、首页配置
4. 手动跑一次验证三版面 + 首页正常渲染

**迁移注意**：旧文章 URL 会变（`/posts/2026-07-31/` → `/ai/2026-07-31/`）。由于是 GitHub Pages 静态站、历史不长（7 月起），不做 301 重定向，接受 URL 变更。若需保留旧链接，可加 Hugo aliases（本规格不默认包含）。

## 8. 决策记录

| 决策点 | 选择 | 理由 |
|---|---|---|
| 内容范围 | 四类全要，只要概览 | 用户定位：概览即可，重要自行深入 |
| 版面颗粒度 | 3 大版面 | 社区并入 AI、深度并入国际，结构清爽 |
| 首页形态 | 变体 B（版面分离 + 今日总览） | 版面分离同时保留「一眼扫完全局」价值 |
| 数据获取方案 | Y（RSS + 受控抓取） | 四类齐全且单点失败不连坐 |
| 生成时机 | 三版面同任务 | 沿用现有 cron，最简单 |
| 行情广度 | 全面覆盖（A股+港股+美股+商品+VIX） | 用户选择 |
| LLM 加工范围 | 仅要闻/研报，结构化数据不加工 | 契合「概览即可」，省 token |
| 测试 | fixture 单测 + mock，不写真实网络集成 | CI 稳定性 |
| 旧 URL | 不重定向 | 历史短，接受变更 |

## 9. 非目标（YAGNI）

- 实时行情推送（静态站每天重建一次，本质是晨间简报）
- 全文抓取与 LLM 深度解析（方案 Z，过度）
- 旧 URL 301 重定向 / Hugo aliases（默认不做）
- 独立仪表盘页（方案 3，性价比低）
- 用户自定义关注股票/板块（本期不做）
